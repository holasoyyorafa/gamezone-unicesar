Module: Implementation and Version Control (Branch: feature/sale-module)

Introduction

During the development of the tasks assigned for the application's sales module, I used artificial intelligence tools in a strategic and measured way. The main objective was to consult syntax references, validate proper distribution under the 4-layer architecture, and receive targeted support with the Git terminal, maintaining full control over the code at all times and ensuring that the authorship and logic reflected my own student criteria.

Strategic Support Points

1. Model Planning and Structure

AI Usage: Quick consultation as a reference guide to structure the attributes and initial constructor of the Sale class.

Purpose: Ensure proper encapsulation of private data and verify consistency with the persistence model before writing the base code, avoiding early architectural errors.

2. Business Logic (SaleService)

AI Usage: Consultative support to brainstorm the validation structure inside the registerSale method.

Purpose: Correctly model the minimum product validation, prior available stock verification, and the logic to decrement inventory in an orderly manner without breaking the exception flow.

3. Git and Terminal Error Resolution

AI Usage: Brief technical support to unblock a minor path detail (pathspec) when packaging atomic commits in the working branch.

Purpose: Streamline the local continuous integration workflow, ensuring that commit messages followed the best practices agreed upon by the team before pushing the branch and opening the Pull Request toward develop.

Conclusion

The use of artificial intelligence functioned exclusively as a technical and methodological support assistant. It did not generate code massively or automatically; instead, it served to resolve specific doubts regarding syntax and workflows, allowing me to consolidate the theoretical and practical knowledge corresponding to this level of the degree.
