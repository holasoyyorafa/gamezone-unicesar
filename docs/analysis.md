About system persons: All people share common attributes like name, ID, and contact phone. Specific roles have unique attributes: clients have an email and purchase history, while sellers have an employee code and a work shift. This is reflected in a hierarchy where a base abstract class Person is extended by Client and Seller. A generic person should not be instantiated because every individual interacting with the system acts under a specific business role (client or seller).  About system products: All products share an identifier, title, price, and stock quantity. Specific features belong to subclasses: video games have a platform, genre, and age rating; consoles have a brand, model, and generation. The base class should declare an abstract method (e.g., getDescription()) to ensure all subclasses implement their own specific details. This utilizes the OOP mechanism of polymorphism.  About sales and entity relationships: A Sale class has an association relationship with Person (specifically one Client and one Seller) and an aggregation/composition relationship with Product (one or more products). The Sale should be responsible for calculating its own total because it holds the internal list of products and their prices, respecting encapsulation.  About business constraints: The constraint of requiring at least one product per sale should be validated in the SaleService layer before creating the Sale object. The automatic inventory update involves the SaleService decreasing the stock of the involved Product entities and using the ProductRepository to persist the changes.  About layered organization: The model layer contains domain classes (entities); persistence handles file reading/writing; service applies business logic; UI handles user interaction. Saving/retrieving logic must not be in domain classes because it violates the single responsibility principle and tightly couples business logic with infrastructure. Dependencies are strict: UI depends on Service; Service depends on Model and Persistence; Persistence depends on Model; Model depends on nothing.
